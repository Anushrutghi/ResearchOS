# v7 — ResearchOS v0.8 Research Ecosystem

**Status: Complete**

## Scope and acceptance checks

Deliver versioned, permission-declared plugin contracts, local projects and collections, role-based collaboration, attributable revisions, authenticated APIs, pagination, and a Python client. Core research workflows must remain usable without installed plugins.

## Delivered

- Added plugin manifest validation for schema/API version, normalized IDs, semantic versions, exact installed dependencies, permissions, capability IDs, and bounded JSON input/output schemas.
- Plugins cannot import or execute arbitrary modules. A capability resolves only to a host-registered adapter. The implemented adapters perform explicit OpenAlex or Crossref read-only literature searches. The action is unavailable unless the plugin is enabled and grants every permission required by its handler; returned data is schema-checked and limited to 2 MB.
- Added high-entropy local bearer tokens, SHA-256-only token storage, first-user administrator assignment, one-time CLI display, and token revocation. Project and plugin APIs require a valid token; plugin installation and enable/disable require an administrator.
- Added durable local projects with owner/editor/reviewer/viewer roles, typed collection references, attributed membership and review events, and revision snapshots. Owner/admin may manage membership, editors may change projects and collections, reviewers may submit review decisions, and viewers may read.
- Added authenticated API routes for projects, memberships, collections, reviews, revisions, and plugin installation/control/actions. Project and revision lists are cursor-paginated with page sizes capped at 100.
- Added the standard-library `ResearchOSClient` for authenticated project, member, collection, review, revision, and plugin-list requests. It validates local inputs, handles pagination, and preserves server status codes in `ResearchOSError`.
- Added the Projects browser view with current-tab token storage, project creation/listing, collection creation, and revision history.
- Documented local user administration, API auth and roles, manifest fields/permissions, adapter limits, and SDK usage in README and the architecture map.

## Limits and follow-up

- Plugin adapters run in the ResearchOS host process and are limited to the built-in read-only Crossref/OpenAlex handlers; third-party executable plugins and write-capable integrations are intentionally unsupported.
- Tokens are local bearer credentials. The web server does not provide TLS, and non-project/non-plugin legacy routes remain local-workspace APIs; do not expose this development server directly to an untrusted network.
- Collection references are typed IDs and are not automatically checked against the corresponding engine store at insertion time. Their records remain attributable but may refer to a removed or unavailable local record.
