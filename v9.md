# v9 — ResearchOS v1.0 Integrated Release

**Status: Complete**

## Scope and acceptance checks

Integrate the research core, evidence and methodology, experiments, agent runtime, writing, project ecosystem, local storage, security, CLI, and browser interface while preserving source and approval provenance.

- A project can progress through supported stages; conditional and unsupported stages are identified.
- Workflows resume and retain source, model, method, configuration, and experiment provenance.
- Experiments run only in the isolated backend; papers use approved records and citations remain verifiable.
- CLI, browser, local installation, API/SDK contracts, plugin documentation, and critical cross-engine tests are ready.

## Implemented so far

- Added authenticated `GET /api/projects/{id}/lifecycle` and `ResearchOSClient.project_lifecycle`. The lifecycle reconciles collection references with saved runs, source documents, claims, study designs, datasets, experiment records, descriptive evaluations, and writing drafts. It distinguishes review and approval states and lists stale references.
- Added a project-card browser view for lifecycle stage status, alongside the existing authenticated project, collection, and revision workflows.
- Run records now report both execution progress and stage availability: researcher review for evidence, conditional methodology guidance, digest-pinned Docker for experiments, review tools without automatic truth verification, and researcher approval for writing.
- Added a deterministic cross-engine test that creates a no-search research run, source PDF and reviewed claim, approved design, dataset evaluation, sandbox-run provenance, approved cited draft/export, and project collection. It restarts the agent runtime and verifies a full backup restore of project, token, workflow, experiment, and writing records.
- Corrected CLI output-format help and errors: research briefs are Markdown, while the separate approval-gated writing engine supports Markdown, LaTeX, DOCX, and PDF exports.
- Set package and CLI version metadata to `1.0.0` and built the installable wheel `researchos-1.0.0-py3-none-any.whl`.
- Connected browser chat to the configured OpenAI-compatible provider, with bounded recent-history context, explicit AI/local response labels, edit-and-resend support, and errors surfaced when the provider is unavailable. Temporary HTTP 503 responses receive two short retries. Local workspace guidance remains available when no provider is configured.

## Remaining

The v1.0 acceptance checks are complete for the local-first foundation. Optional AI provider credentials enable browser chat and the source-grounded proposal features; the local research, evidence, methodology, experiment, project, and writing workflows do not require them.

Known platform and scope limits are recorded across the milestone notes: the server has no TLS and should stay on localhost unless a trusted proxy protects every route; backups are per-file verified rather than cross-engine transactional; third-party executable plugins are unsupported; advanced PDF normalization and publisher-specific compliance remain follow-up work; the Docker daemon, kernel, and pinned image remain trusted components; and optional OCR was not installed in this environment.
