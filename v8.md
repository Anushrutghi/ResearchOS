# v8 — ResearchOS v0.9 Reliability and Scientific QA

**Status: Complete**

## Scope and acceptance

Harden recovery, error handling, backups, health reporting, input/archive bounds, local security boundaries, scientific quality checks, and operating instructions. Avoid adding large research engines in this stabilization release.

## Delivered

- Added `researchos backup`, `researchos verify-backup`, and `researchos restore`. Archives enumerate regular files and SHA-256 hashes, reject symlinks and unsafe archive entries, verify each member before restore, enforce file and byte bounds, and restore only to a new destination. The user-token store is restored with owner-only permissions. Backups must be outside the live output directory.
- Added `researchos quality`, `/api/quality`, and the browser Verification panel. Checks report JSON readability, dataset/PDF content hashes, experiment source/artifact hashes, and claim review state. Each check is visible on its own; no scientific-validity score or claim-truth assertion is produced.
- Added `/api/health` with non-secret storage-location and progress-file readiness checks.
- Reviewed a project ownership edge case, fixed owner role reassignment, and expanded revision events to retain collection contents and review decisions. Cursor parsing and plugin schemas now reject malformed encodings and unsupported schema keywords.
- Documented the trust boundary: the built-in server has no TLS and legacy browser APIs are not bearer-authenticated. It should remain bound to localhost; a trusted proxy must protect every route before remote exposure.
- Exercised backup/restore, archive corruption rejection, dataset tampering detection, health/quality routes, CLI paths, restored account/project/agent state, and (during v1.0) the whole workspace lifecycle.

## Verification

The v0.9 regression run passed **111 tests with 3 intentional skips** (optional OCR and opt-in Docker checks). JavaScript syntax, progress JSON, Python compilation, and `git diff --check` passed. The subsequent integrated suite includes additional v1.0 coverage. No external AI request was made.

## Limits

- Backups hash and verify each stored file but do not lock independent writers into one cross-engine transaction. Take backups while ResearchOS is idle for strongest consistency.
- Resource bounds and integrity hashes do not replace operating-system access control, separate backup retention, or infrastructure monitoring.
- The Docker daemon, kernel, and configured digest-pinned image remain within the experiment trust boundary.
