# v2 — ResearchOS v0.3 Evidence Intelligence Engine

**Status: Complete (core v0.3 acceptance passed; improvements remain)**

## Release objective

Turn discovered publications and researcher-provided documents into traceable, reviewable claims and evidence relationships. Extracted claims remain provisional until reviewed. Contradictions must account for differences in methods, populations, conditions, and definitions.

## Scope

- Document intelligence: PDF import, page-aware text extraction, section/abstract/method/result identification, table/reference extraction where supported, scanned-PDF detection, and honest OCR capability reporting.
- Claim records: claim ID, text, document/page/section source, timestamp, extraction method, and verification status.
- Evidence mapping and categories: experimental, observational, theoretical, statistical, literature-supported, interpretation, hypothesis, proposed experiment, and unverified claim.
- Lightweight knowledge graph for papers, authors, claims, topics, datasets, experiments, methods, and findings, with typed relationships.
- Contradiction candidates that preserve context and require human review.
- Browser views for documents, claims, source passages, evidence relationships, and verification state.

## Acceptance checks

- Imported document text and every extracted passage retain document and page provenance.
- Claims link to original passages; AI extraction, when available, is provisional and source-linked.
- Unsupported claims are surfaced as unverified.
- Contradiction candidates explain their source context and are not treated as confirmed contradictions automatically.
- Graph relationships and extraction provenance persist locally.
- Unsupported, malformed, scanned, or unreadable documents report what failed without inventing text.

## Delivered so far in this v0.3 build

- Responsive light browser workspace with persistent local chats, new chat, edit-and-resend, voice input where Web Speech is supported, input/output style settings, research-run creation, library/evidence navigation, and nine-release status view.
- Researcher-selected PDFs are stored locally under a SHA-256 filename with original name, import timestamp, origin, extraction method/status, metadata, and page text.
- `pypdf` extraction preserves page numbers; title/author metadata, DOI text, and conservative exact section headings are extracted where present.
- The PDF extractor preserves reference lines with page, raw text, and cautious DOI/year candidates. It groups obvious pipe/tab/whitespace-separated lines into page-located table-row candidates, retaining cells and warning that layout may differ from the source.
- Scanned/empty PDFs, malformed PDFs, page/character limits, optional OCR status, and partial reference/table extraction states are represented explicitly.
- Optional OCR uses pypdfium2/Pillow page rendering plus the system Tesseract executable; only textless pages are processed, with 100-page and per-page timeout bounds.
- Researchers can enter source-linked claims with page and passage, classify evidence, keep claims provisional, mark them reviewed, and create proposed typed relationships including possible contradictions.
- Proposed evidence relationships can now be explicitly reviewed or rejected with a required researcher context note. The review view places each claim beside its source passage and page link; a decision records researcher judgment but does not independently prove scientific support or contradiction.
- When an AI provider is configured, researchers can explicitly compare a selected pair of claims and their passages. The model must return a proposed supports/contradicts/challenges/uncertain relation, confidence label, rationale, and possible contextual differences; the user must still save and review the relationship.
- Optional AI claim suggestions are available through an explicit action when `RESEARCHOS_AI_PROVIDER=openai_compatible`, `RESEARCHOS_AI_MODEL`, and `RESEARCHOS_API_KEY` are configured. Only the selected page is sent to the configured OpenAI-compatible endpoint; remote endpoints must use HTTPS (HTTP is allowed only for localhost development). The endpoint response is validated and suggestions remain provisional until the researcher saves and reviews them. No key or provider response credentials are exposed in workspace status.
- A local JSON graph stores document, paper, author, and claim nodes, with proposed paper-identity/authorship links marked as unverified PDF metadata and claim-to-source provenance edges; extracted page text and claims can be searched locally.
- The browser renders the local graph as an SVG and links each claim to its original PDF page.
- Local HTTP routes, packaging of browser assets, and offline unit/integration tests have been added.

## Feedback and current limits

- Browser chat saves messages and reports workspace status; it does not generate research analysis. AI is used only for the separate, explicitly requested claim-suggestion action when a compatible provider is configured.
- AI extraction is limited to short selected page text and the OpenAI-compatible chat completions request format. It does not verify whether a candidate is supported; the researcher must check the displayed source passage. Provider access requires network connectivity and may incur provider charges.
- AI relationship comparison is opt-in and limited to a user-selected pair. Suggestions can miss or misread study design details; confidence is model-reported, not calibrated, and no batch contradiction detector or autonomous literature-wide analysis exists.
- OCR is optional and has a local Tesseract smoke test; it requires the `ocr` extra plus a system Tesseract installation. Table cells and DOI/year reference fields are heuristic candidates, not verified table structures or normalized citations. Source accessibility checks and automatic verification are not implemented.
- Section recognition is heuristic and exact-heading based; extracted metadata can be missing or incorrect and needs researcher review.
- PDF parsing has upload/page/text size caps but has not received the full v0.9 untrusted-document security review.
